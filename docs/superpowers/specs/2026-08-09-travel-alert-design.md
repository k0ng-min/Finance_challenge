# 여행지 위험도(외교부 여행경보) — 설계

작성 2026-08-09.

> **개정됨(2026-08-11).** 인증키를 받아 실제 데이터를 채우자 아래 "같은 나라가 여러
> 지역으로 나뉘어 오면 가장 높은 단계를 대표로 쓴다"는 규칙이 틀렸다는 것이 드러났다.
> 일본(후쿠시마 30km)·태국·필리핀 같은 인기 여행지가 전부 3·4단계로 잡힌다.
> [2026-08-11 개정 설계](2026-08-11-travel-alert-region-design.md)를 함께 읽을 것.

## 무엇을 하려는가

여행 준비 화면에서 목적지 국가의 **외교부 여행경보 단계**를 보여주고, 경보가 높은
지역이면 그 보험사 약관의 **전쟁·내란 면책 조항 원문**을 근거로 함께 알린다.

지금 `risk_profile.risk_level`은 활동과 여행일수만 본다. 시리아에 가든 일본에 가든
"관광"이면 똑같이 낮음이 나온다. 목적지가 위험도에 전혀 반영되지 않는다.

## 왜 이 축인가

여행경보가 높은 지역은 여행자보험에서 **실제로 보상 여부가 갈리는** 구간이다.
6개사 약관을 확인한 결과 근거가 충분했다.

| 키워드 | 조항 수 |
|---|---|
| 전쟁 | 46 |
| 폭동 | 37 |
| 내란 | 36 |
| 혁명 | 36 |
| 무력 | 35 |
| 테러 | 8 |

그리고 사고유형 `SPC_WAR_TERROR`(전쟁·테러 면책)에 **6개사 전부, 면책 조항 15건**이
이미 매핑돼 있다. 새 판단 로직을 만들 필요 없이 기존 기계를 그대로 쓴다.

## 데이터

**출처**: 외교부 국가·지역별 여행경보 (공공데이터포털)

```
http://apis.data.go.kr/1262000/TravelAlarmService2/getTravelAlarmList2
응답: 한글국가명, 영문국가명, ISO 2자리 코드, 경보단계, 지역타입, 경보내용, 작성일
```

단계: 1 여행유의 / 2 여행자제 / 3 출국권고 / 4 여행금지

**보험료(`premiums.json`)와 같은 방식으로 다룬다.** 한 번 받아 출처·수집일과 함께
저장소에 커밋하고, 런타임은 그 스냅샷을 읽는다. 인증키가 있으면 갱신할 수 있고,
없어도 앱은 정상 동작한다 — 심사위원이 키 없이 열어도 화면이 비지 않는다.

```
backend/app/crawl_travel_alerts.py   외교부 API → data/travel_alerts.json
backend/data/travel_alerts.json      스냅샷(출처 URL·수집일 포함)
backend/app/seed_travel_alerts.py    JSON → travel_alert 테이블
```

## 약관과 어떻게 잇는가

```
목적지 국가
  ↓ travel_alert 조회
경보 단계
  ↓ 3단계(출국권고) 이상일 때만
SPC_WAR_TERROR에 매핑된 그 보험사 면책 조항
  ↓
제한조건 finding (조항 원문 인용)
```

| 경보 | 결과 |
|---|---|
| 1 여행유의 / 2 여행자제 | 배지만 (정보) |
| 3 출국권고 / 4 여행금지 | 제한조건 카드 + 약관 면책 원문 |

## 지키는 경계

**경보 단계 자체를 보상 판정의 근거로 쓰지 않는다.** 외교부 자료와 보험 약관은 별개
출처다. 화면 문구도 이 구분을 지킨다.

- ❌ "이 지역은 보상되지 않습니다"
- ⭕ "이 보험사 약관에 전쟁·내란 지역 면책 조항이 있습니다" + 원문 인용

그 밖에:

- **보험사 순위 점수에 넣지 않는다.** 약관 근거가 아니라 외부 자료이기 때문이다
  (보험료를 순위에서 뺀 것과 같은 이유).
- 경보 자료에 없는 나라는 추측하지 않고 비워 둔다.
- 국가명이 매칭되지 않으면 조용히 넘어가지 않고 확인 불가로 표시한다.

## 화면

- 여행 준비 STEP 1: 국가를 고르면 그 자리에 경보 배지
- 결과 화면: 3·4단계면 제한조건 카드

## 테스트

- 스냅샷의 국가명이 앱의 국가 목록(`COUNTRIES`)과 실제로 매칭되는지
- 3·4단계 → 제한조건 생성 + 근거 조항 존재
- 1·2단계 → 제한조건 없음
- 인용문이 조항 원문의 부분 문자열인지
- 경보 데이터가 아예 없어도 여행 생성이 정상 완료되는지

## 알려진 제약

공공데이터포털 인증키가 있어야 스냅샷을 채울 수 있다. 키가 없는 동안에는 파이프라인만
동작하고 경보 배지·제한조건은 나타나지 않는다 — 없는 데이터를 지어내지 않기 위함이며,
키를 넣고 `crawl_travel_alerts`를 한 번 돌리면 그대로 채워진다.
