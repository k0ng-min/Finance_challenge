# 여행경보 — 국가가 아니라 지역 단위로 (설계 개정)

작성 2026-08-11. [2026-08-09 여행경보 설계](2026-08-09-travel-alert-design.md)의 개정이다.

## 왜 고치는가

08-09 설계는 실제 데이터 없이 만들었다. 공공데이터포털 인증키를 받아 스냅샷을 채우자
전제 하나가 깨졌다.

원래 규칙은 이랬다.

> 같은 나라가 여러 지역으로 나뉘어 오면 가장 높은 단계를 대표로 쓴다. 낮은 쪽을
> 대표로 삼으면 실제보다 안전해 보이게 된다.

데이터가 없을 때는 합리적인 보수적 선택이었다. 실제 응답 208건을 받아보니 결과가 이렇다.

| 나라 | 최고단계 | 그 단계가 걸린 실제 범위 |
|---|---|---|
| 일본 | 3 출국권고 | 후쿠시마 원전 반경 30km 이내 |
| 태국 | 3 출국권고 | 파타니·나라티왓·얄라 주 |
| 필리핀 | 4 여행금지 | 민다나오 잠보앙가, 술루·바실란 타위타위 군도 |
| 멕시코 | 3 출국권고 | 치아파스주, 시날로아주 |
| 인도 | 3 출국권고 | 카슈미르, 카르길 |

원래 규칙대로면 **도쿄 여행자에게 "외교부가 일본에 여행경보 3단계(출국권고)를
발령했습니다"와 6개사 전쟁·내란 면책 조항**이 뜬다. 방콕·세부·칸쿤도 같다.

3·4단계 72개국 중 52개국이 `일부` 지역 경보다. 예외가 아니라 다수다.

경고를 과하게 하는 것은 안전한 쪽이 아니다. 모든 인기 여행지에 "출국권고"가 뜨면
사용자는 경보 자체를 무시하게 되고, 정말 위험한 시리아·우크라이나에서도 똑같이
무시한다. 그러면 이 기능은 있으나 마나가 된다.

## 무엇으로 바꾸는가

외교부 여행경보는 **국가 단위가 아니라 지역 단위**다. 데이터 모델이 그 사실을 반영한다.

### 기본단계와 지역경보를 나눈다

한 나라의 경보 행들을 두 가지로 읽는다.

```
baseline  그 나라 일반 지역의 단계
  1. region_ty == '전체' 행이 있으면 그 단계                    87개국
  2. 없으면 "…를 제외한 (전) 지역" 행 중 최저 단계             47개국
     정규식 /제외한?\s*전?\s*지역/
  3. 둘 다 없으면 None — 특정 지역에만 경보가 걸린 나라         11개국

regions   baseline이 아닌 나머지 행들 (단계 + 지역 서술)
```

2번에서 **'제외'라는 글자만 보면 안 된다.** 외교부 문구는 특정 지역을 서술하면서
괄호로 단서를 다는 일이 잦고, 그것까지 나머지 전역으로 읽으면 엉뚱한 단계가 잡힌다.

| 나라 | 문구 | 글자만 볼 때 | 실제 |
|---|---|---|---|
| 시리아 3단계 | 골란고원 일부(…4km 이내 지역 **제외**) | baseline 3 | 골란고원 얘기, baseline은 4단계 |
| 러시아 3단계 | 북카프카즈(…), 우크라 접경(4단계 **제외** 로스토프…) | baseline 3 | 모스크바는 경보 없음 |
| 이집트 3단계 | 중·북부 시나이 반도(1,2단계 지역 **제외**) | baseline 3 | 카이로는 경보 없음 |

'제외' 뒤에 '지역'이 따라오는 형태만 나머지 전역으로 본다. 이 구분이 없으면
모스크바·카이로 여행자에게 자동으로 전쟁·내란 면책 조항이 붙는다.

2번에서 **최저**를 쓰는 이유: 이런 행이 여러 개 잡히면 더 좁은 범위를 말하는 쪽이 높은
단계다. 나라 전체에 해당하는 것은 그중 가장 낮은 단계다(필리핀 = 2단계).

판정에 쓴 근거(`전체행` / `나머지행` / `국지적`)를 응답에 함께 싣는다. 휴리스틱이
왜 그렇게 판단했는지 화면과 심사 자리에서 설명할 수 있어야 한다.

### 면책 조항을 언제 꺼내는가

```
baseline >= 3                          → 자동 연결      33개국
사용자가 3·4단계 지역 방문을 체크       → 그 지역 근거로 연결
그 외                                  → 배지에 지역만 명시, 연결 안 함
```

자동 연결 31개국: 시리아, 우크라이나, 이라크, 이란, 이스라엘, 아프가니스탄, 예멘,
미얀마, 팔레스타인, 레바논, 리비아, 수단, 소말리아, 니제르 등.

빠지는 나라: 일본, 태국, 필리핀, 멕시코, 인도, 캄보디아, 러시아, 이집트,
사우디아라비아, 요르단 등 — 배지에 "일부 지역 3단계: 후쿠시마 원전 반경 30km
이내"처럼 **어디가** 위험한지 적어 보여준다.

## 데이터 수집

크롤러는 208건을 **접지 않고 그대로** 저장한다. 지금은 국가별 최고단계 1건으로 접어
145건만 남기는데, 지역 정보가 여기서 소실된다. 크롤러가 스스로 밝힌 원칙
("받은 값을 가공하지 않는다")에도 그대로 두는 쪽이 맞다.

`travel_alert` 테이블은 이미 행 단위(`country_name`, `level`, `region_type`, `note`)라
스키마 변경이 없다.

**baseline 판정은 크롤러가 아니라 서비스에서 한다.** 스냅샷에 구워 넣으면 휴리스틱을
고칠 때마다 재수집해야 하고, 인증키가 없는 사람은 고칠 수도 없다.

## 화면

경보가 있는 나라를 고르면 **여행경보만 다루는 스텝이 하나 늘어난다.** 목적지 스텝에
같이 얹으면 동반자·나이·성별 입력에 묻혀 그냥 지나치게 되는데, 이건 지나치면 안 되는
정보다. 경보 자료가 없는 나라(미국·대만·싱가포르 등 대다수)는 이 스텝 자체가 생기지
않아 기존 흐름이 그대로다.

```
STEP 2 · 여행경보
일본에 여행경보가 있어요
외교부가 발령한 자료입니다. 보상 여부를 판단한 결과가 아닙니다.

  일부 지역 3단계  출국권고
  후쿠시마 원전 반경 30km 이내 및 일본 정부 지정 피난지시구역
                                          외교부 발령 · 확인

  아래 지역이 여행 경로에 포함되나요?
  □ 3단계 출국권고 · 후쿠시마 원전 반경 30km 이내 및 …
  체크하시면 각 보험사 약관의 전쟁·내란 면책 조항을 원문과 함께 보여드립니다.
  해당 지역에 가지 않으신다면 그냥 넘어가셔도 됩니다.
```

체크하지 않으면 아무 일도 일어나지 않는다 — 도쿄 여행자는 그냥 지나간다. 체크하면
결과 화면에 면책 조항 카드가 지금과 **똑같은 finding 경로로** 붙는다(새 표시 경로를
만들지 않는다).

`baseline >= 3`인 나라는 체크 없이 자동이다.

스텝이 하나 끼면 뒤 번호가 밀리므로 스텝 번호는 하드코딩하지 않고 렌더 시점에 매긴다.

## API

- `GET /trips/travel-alerts/{country}` 신설 — STEP 1에서 조회. 인증 불필요(공개 자료).
  응답: `{ baseline: {level, label, basis, note, ...} | null, regions: [{alert_id, level, label, note}], source, source_url, issued_on }`
- `POST /trips`에 `visiting_alert_region_ids: list[int]` 선택 필드 추가.
  **서버는 이 id가 실제로 그 목적지의 3·4단계 지역 행인지 검증한다** — 다른 나라의
  alert_id를 넣어 면책 카드를 억지로 띄우는 것을 막는다.

## 지키는 경계 (08-09에서 그대로 유지)

- 경보 단계 자체를 보상 판정의 근거로 쓰지 않는다. "보상되지 않습니다"가 아니라
  "이 보험사 약관에 전쟁·내란 면책 조항이 있으니 원문을 확인하고 보험사에 직접
  물어보라"까지만 한다.
- 보험사 순위 점수에 넣지 않는다.
- 경보 자료에 없는 나라는 추측하지 않고 비운다.

여기에 하나를 더한다.

- **경보 범위를 넓혀 말하지 않는다.** 일부 지역 경보를 국가 전체 경보처럼 표시하지
  않는다. 이것이 이번 개정의 전부다.

## 테스트

기존 8건은 유지하고 아래를 더한다.

- baseline 판정: 전체행 / 제외행최저 / 국지적 세 경로 각각
- 필리핀형(제외 행이 여러 단계에 걸침) → 최저가 뽑히는지
- 일본형(국지적) → 체크 없으면 면책 없음, 체크하면 면책 있음
- 시리아형(baseline 3 이상) → 체크 없이 면책
- 남의 나라 alert_id를 넣으면 무시되는지
- 커밋된 실제 스냅샷 기준 회귀: 일본·태국·필리핀·인도·멕시코가 자동 연결 대상에서
  빠지고 시리아·우크라이나·이라크는 들어가는지

마지막 항목은 누가 로직을 되돌렸을 때 바로 잡히게 하려는 것이다. 이 기능이 틀리는
방식은 "안 뜨는 것"이 아니라 "엉뚱한 데 뜨는 것"이라서다.

## 알려진 제약

`제외한 지역` 문구에 기대는 휴리스틱이다. 외교부가 표현을 바꾸면 그 나라는 `국지적`으로
떨어지고, 그러면 **면책 조항이 자동으로 붙지 않는 쪽**으로 실패한다. 조용히 과잉
경고하는 것보다 낫다고 보고 이 방향을 택했다. 판정 근거를 응답에 싣는 것도 이때
어느 나라가 어떻게 판정됐는지 눈으로 확인할 수 있게 하기 위함이다.

`국지적`이 20%를 넘으면 테스트가 깨진다 — 문구가 바뀌어 기능이 통째로 조용히
무력화되는 것을 잡기 위해서다(현재 11/145).

수집 응답에는 `&middot;` 같은 HTML 엔티티가 섞여 온다. 크롤러에서 풀어 저장한다 —
React가 이스케이프하므로 그대로 두면 화면에 `로스토프&middot;벨고로드`로 보인다.
