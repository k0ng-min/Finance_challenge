1. MVP 구현 범위*

아래는 배포 URL에서 실제로 동작하는 범위이며, 미구현·향후 예정 기능은 포함하지 않았다.

  • 지식베이스 — 6개 손해보험사 여행자보험 약관을 조항 단위로 정제해 적재 완료: 조항 441건, 담보 141건, 표준담보 45종, 사고유형 대분류 8종·세부유형 31종, 조항–사고유형 매핑 568건, 수치조건 174건, 담보–필요서류 매핑 503건(연결률 100%), 등급별 보장금액 378행, 실제 보험료 2,062행.
  • 화면 — 홈, 내 여행 준비, 내 보험, 사고 접수, 청구 전 점검, 보험료 비교, 약관 형광펜, 현지에서, 사고 시뮬레이션, 계정 — 총 10개 화면이 동작한다.
  • 인증 — 카카오·구글 소셜 로그인, 이메일+비밀번호 로그인, 게스트 이용(로그인 불필요)이 모두 동작한다.
  • 생성형 AI — 사고 자유서술 구조화, 사고유형 2단계 분류, 사고별 확인 질문 2단계 생성, 조항·서류 상황별 설명, 약관 형광펜 구간 추출, 순위 보조 점수, 현지어 서류 요청문 생성이 실제로 호출된다.
  • 검증 — 백엔드 자동화 테스트 272건 통과(인용 검증·데이터 무결성·순위 재현성·결측 처리 포함).

기능명기능 설명 관련 화면구현 상태

기존보험 중복·공백 진단 보유한 실손·상해·일상생활배상책임과 여행자보험이 겹치는 담보/비는 담보를 약관 근거와 함께 제시. 근거를 못 찾으면 “확인불가”로 표시 내 여행 준비 / 내 보험완료

AI 맞춤 확인 질문(2단계) 미리 만든 질문지가 아니라, 사고 내용을 읽고 필요한 질문을 그 자리에서 생성. 1단계(대분류 확인) 답변을 읽고 2단계(세부유형 확인) 질문을 새로 생성. 각 단계가 한 화면에 뜨고 예/아니오 버튼과 입력칸이 섞여 있으며, 자유 입력칸이 함께 있음 사고 접수완료
담보·조항 매칭 확정된 사고유형에 직접/조건부/면책으로 매핑된 조항 중, 사용자가 등록한 실제 담보만 추림. 사고 상황의 활동이 면책 조항 원문에 언급돼 있으면 면책을 우선 표시 사고 접수 결과완료
필요 서류 안내·체크 담보별 필요 서류를 표준 서류 코드로 제시하고 확보 여부를 체크. 서류 사진 업로드 시 형식 점검 청구 전 점검완료
청구 전 누락·모순 점검 LLM을 쓰지 않는 결정적 규칙으로 보험기간 불일치, 정보 누락, 입력값 모순(예: 수술은 받았는데 입원은 아니오)을 점검 청구 전 점검완료
약관 형광펜 사고와 직접 관련된 조항 구간을 노란색으로 표시. 인용이 조항 원문의 부분 문자열인지 검증 후에만 표시. 표준약관과의 대조도 제공 약관 형광펜완료
현지에서(해외 서류 챙기기) 목적지 언어로 필요 서류 요청 문구를 현지어·한국어 병기로 생성. HTML 파일 또는 이미지로 저장해 통신 없이 열람 가능 현지에서완료
사고 시뮬레이션 가입 전에 “이런 사고가 나면 어떻게 되는지”를 6개사 기준으로 미리 확인(직접/조건부/면책/확인불가) 사고 시뮬레이션완료
여행경보 안내 목적지의 외교부 여행경보 단계를 표시하고, 해당 지역 방문 여부를 체크한 경우에만 관련 면책 안내를 노출 내 여행 준비완료
계정·기록 관리 카카오·구글·이메일 로그인, 게스트 이용, 여행/사고/보험 기록 조회·수정·삭제, 회원 탈퇴 계정완료

3. 사용자 이용 흐름*

A. 가입 전 — 나에게 맞는 보험 찾기

① 배포 URL 접속(로그인 불필요) → ② 홈에서 ‘내 여행 준비’ 선택 → ③ 목적지·기간(달력에서 출발일→도착일)·동행·활동·나이·성별·걱정되는 사고유형·기존 보유 보험 입력 → ④ 비교 기준(안정형/실속형/최대보장형/간편청구형/균형형) 선택 → ⑤ ‘보험사 순위 확인하기’ → ⑥ 6개사 순위와 5개 축 기여도·오각형 그래프 확인 → ⑦ 상단에서 실속/표준/고급 등급을 바꾸면 순위가 다시 계산됨 → ⑧ 보험사 카드를 눌러 담보 추천·약관 근거 확인 → ⑨ 기존보험 중복·공백 진단 확인

B. 사고 후 — 무엇을 받을 수 있는지 확인하기

① 홈에서 ‘사고가 발생했어요’ 선택 → ② 청구할 보험과 여행 선택(없으면 그 자리에서 새 여행 등록) → ③ 사고 상황을 문장으로 입력 → ④ 1단계 확인 질문(한 화면, 예/아니오·입력칸·기타) 답변 → ⑤ 2단계 확인 질문 답변 → ⑥ 결과 화면에서 청구검토 담보·근거 조항·수치 조건·필요 서류 확인 → ⑦ ‘필요 서류 체크하러 가기’로 이동해 서류 확보 여부 점검 → ⑧ 조항 카드에서 약관 형광펜으로 근거 원문 확인

C. 여행 중 — 현지에서 서류 챙기기

① 홈에서 ‘현지에서’ 선택 → ② 목적지·상황 선택 → ③ 현지어·한국어 병기 서류 요청 카드 확인 → ④ HTML 파일 또는 이미지로 저장해 통신이 끊긴 상태에서도 열람

4. AI 및 데이터 처리 방식*

(1) AI가 수행하는 역할과 입력·출력

적용 지점입력출력근거 통제
사고 자유서술 구조화사고 서술 문장부위·진단·입원·수술·의료비 등 구조화 필드 + 신뢰도신뢰도 미달 시 사용자에게 재확인
사고유형 분류(2단계)사고 서술, 확인 질문 답변, 세부유형 후보 목록대분류 코드 → 세부유형 코드 + 신뢰도확신이 낮으면 세부유형을 추정하지 않고 대분류에 보류
확인 질문 생성(2단계)사고 서술, 이미 확보된 값, 1단계 답변, 세부유형 후보질문 3~6개(질문문·대상 필드·답변 형태·중요도)담보 판단에 쓰이는 필드명을 강제, 앞 단계에서 물은 항목 제외
조항·서류 설명약관 조항 원문, 사고 맥락쉬운 말 설명 문장설명이 실패해도 기본 문구로 대체(흐름 유지)
약관 형광펜조항 원문, 사고 맥락하이라이트할 구간원문 부분 문자열 검증 통과 시에만 표시
보험사 순위 보조 점수약관 근거 축, 등급별 보장금액, 여행 정보보험사별 0~100 점수와 이유 문장최종 점수의 20%만 반영, 실패 시 수식 점수만으로 동작
현지어 서류 요청문목적지 언어, 필요 서류 목록현지어·한국어 병기 요청 문구서류 목록 자체는 약관 기반 결정적 매핑

※ 보상 여부의 최종 판정·금액 산정·약관에 없는 사실의 생성은 AI가 하지 않는다. 이 셋은 결정적 규칙과 약관 원문이 담당한다. 순위는 R로 산출한 가중치 모델이 80%를 차지해 같은 입력에는 항상 같은 결과가 나온다.

(2) 사용 데이터

  • 약관 지식베이스 — 6개사 공개 약관 PDF에서 정제한 조항·담보·사고유형 매핑·수치조건·필요서류(위 1항 수치 참조). 서비스가 제시하는 모든 근거는 이 데이터에서 나온다.
  • 등급별 보장금액·실제 보험료 — 각 사 공시 자료 및 다이렉트 계산기에서 직접 조회. 출처·URL·수집일·산출 전제를 행 단위로 저장한다.
  • 보조 데이터 — 표준약관, 외교부 여행경보, 손해보험협회 공시, 항공 지연 통계.
  • 사용자 입력 데이터 — 여행 정보(목적지·기간·동행·활동), 사고 서술과 답변, 보유 보험 종류.

(3) 개인정보·민감정보 처리 여부

  • 수집 항목 — 닉네임, 나이, 성별, 이메일(소셜 로그인 시 제공자에서 전달), 소셜 로그인 식별자, 사용자가 직접 입력한 여행·사고·보유 보험 정보.
  • 수집하지 않는 항목 — 주민등록번호, 계좌·카드번호, 실제 증권번호, 의료기록 원본 등 민감정보는 수집하지 않는다. 서류 사진 업로드는 형식 점검용으로만 쓰이며 외부로 전송하지 않는다.
  • 로그인 없이 이용 가능 — 게스트로 전 기능을 쓸 수 있고, 게스트 데이터는 새 사고 접수 시 정리된다.
  • 동의·삭제 — 이메일 회원가입 시 이용약관·개인정보 수집·이용, 만 14세 이상 확인 동의를 받는다. 가입 도중 이탈하면 그때까지 만들어진 계정을 삭제한다. 계정 화면에서 여행·사고·보험 기록을 개별 삭제하거나 회원 탈퇴로 일괄 삭제할 수 있다.
  • 외부 전송 — 생성형 AI 호출 시에는 사고 서술·답변·약관 조항 등 판단에 필요한 텍스트만 전달하며, 이메일·로그인 식별자 등 계정 정보는 전달하지 않는다.
  • 보안 — 비밀번호는 bcrypt로 해시 저장, 요청 빈도 제한과 보안 HTTP 헤더를 적용했다. 소유자 검증을 통해 다른 사용자의 여행·사고 기록에 접근할 수 없다.

5. MVP 검증 방법*

(1) 접속 및 계정

  • 배포 URL: https://travel-insurance-web.onrender.com/
  • 별도 계정이 필요 없습니다. 로그인 없이 게스트 상태로 아래 모든 기능을 그대로 확인할 수 있습니다. (로그인 동작을 확인하시려면 카카오·구글 로그인 또는 이메일 회원가입을 이용해 주세요.)
  • 첫 접속 시 30~60초 정도 로딩될 수 있습니다. 무료 호스팅 특성상 일정 시간 접속이 없으면 서버가 대기 상태로 전환되며, 첫 요청 시 다시 기동됩니다. 화면에 손글씨 로딩 애니메이션이 표시되는 동안 기다려 주시면 정상 진입합니다.

(2) 확인 절차 — 시나리오 A: 맞춤 보험사 순위 (약 3분)

  • 홈 → ‘내 여행 준비’ → 목적지 일본, 동행 혼자, 성별·나이 남 / 30 입력 → 다음
  • 여행 기간: 달력에서 출발일을 누르고 이어서 도착일을 누르면 두 날짜 사이가 띠로 이어집니다(예: 8월 5일 → 8월 9일)
  • 걱정되는 사고유형에서 상해·휴대품 선택 → 활동 스키 선택 → 비교 기준 균형형 선택 → ‘보험사 순위 확인하기’
  • 예상 결과 — 6개사 순위가 나오고, 각 카드에 5개 축(고른 사고에 보장금액이 커요 / 약관 근거가 탄탄해요 / 보험료가 합리적이에요 / 이미 든 보험과 안 겹쳐요 / 이번 여행 위험에 맞아요)의 점수·기여도와 오각형 방사형 그래프(주황 점선 = 6개사 평균)가 표시됩니다.
  • 핵심 확인 포인트 — 상단의 실속 / 표준 / 고급을 번갈아 누르면 순위가 실제로 바뀝니다. 등급 간 보장금액 차이가 큰 보험사는 순위가 오르내리고, 세 등급 금액이 같은 항목은 순위에 영향을 주지 않습니다. 같은 조건을 다시 선택하면 항상 같은 순서가 나옵니다.

(3) 확인 절차 — 시나리오 B: 사고 접수와 약관 근거 (약 3분)

  • 홈 → ‘사고가 발생했어요’ → 청구할 보험사와 여행 선택
  • 사고 내용에 “파리에서 휴대폰을 소매치기당했어요” 입력 → 다음
  • 1단계 확인 질문이 한 화면에 표시됩니다(예/아니오 버튼과 입력칸이 섞여 있고, 맨 아래 자유 입력칸이 있습니다). 답한 뒤 계속하면 2단계 질문이 이어집니다.
  • 예상 결과 — 청구검토 담보와 함께 약관 조항 원문·조 번호·쪽수가 인용되어 표시되고, 담보별 필요 서류가 나옵니다. 조항 카드를 누르면 약관 형광펜 화면에서 관련 구간이 노란색으로 표시됩니다.
  • 근거 없는 답을 내지 않는 것을 확인하시려면, 등록한 보험이 다루지 않는 사고를 입력해 보세요. “청구 가능”이라고 말하는 대신 관련 약관을 찾지 못했다고 답합니다.
  • 다른 입력 예시: “계단에서 넘어져 발목이 부러졌어요”(상해), “항공편이 6시간 지연됐어요”(운송), “호텔 객실 유리를 깨뜨렸어요”(배상책임)

(4) 확인 절차 — 시나리오 C: 현지에서 서류 챙기기 (약 1분)

  • 홈 → ‘현지에서’ → 목적지(예: 베트남)와 상황 선택 → 현지어·한국어 병기 서류 요청 카드 확인
  • 예상 결과 — HTML 파일 또는 이미지로 저장할 수 있으며, 저장한 파일은 외부 리소스를 참조하지 않아 통신이 끊긴 상태에서도 열립니다.

(5) 실행 환경 · 브라우저

  • 최신 Chrome / Edge / Safari(데스크톱·모바일)에서 동작을 확인했습니다. 별도 설치나 확장 프로그램이 필요 없습니다.
  • 데스크톱과 모바일 화면 폭에 모두 대응합니다(달력은 넓은 화면에서 2단, 좁은 화면에서 하단 시트로 표시됩니다).
  • Internet Explorer는 지원하지 않습니다.

(6) MVP 단계의 제한사항

  • 본 서비스는 정보 제공을 목적으로 하며, 실제 보험 가입·청구 접수는 수행하지 않습니다. 최종 보상 여부는 보험사의 심사에 따릅니다.
  • 비교 대상은 6개 손해보험사의 여행자보험으로 한정됩니다.
  • 일부 자료가 아직 채워지지 않은 자리가 있으며, 이 경우 추정으로 메우지 않고 그 사실을 화면에 밝힙니다.
    • 카카오페이손해보험의 배상책임·운송·여행변경은 확보한 약관 원문에 해당 특약 조항이 수록되어 있지 않아 근거 조항이 제시되지 않습니다.
    • DB손해보험은 실제 보험료를 아직 수집하지 못해 순위에서 보험료 축을 제외하고 나머지 축으로 재정규화합니다(자료가 없다는 이유로 불리해지지 않도록 설계).
    • 메리츠화재는 실속·표준 두 등급만 판매하여 고급 등급 비교에서는 제외되며, 그 사실을 화면에 함께 표시합니다.
  • 무료 호스팅을 사용하여 첫 접속 시 대기 시간이 발생할 수 있으며, 재배포·재시작 시 이용 중 생성된 사용자 데이터(계정·여행·사고 기록)는 초기화될 수 있습니다. 약관 지식베이스는 저장소에 포함되어 항상 동일하게 유지됩니다.
  • 생성형 AI 호출이 일시적으로 실패하는 경우, 규칙 기반 대체 경로로 동작합니다. 이때도 근거 없는 답을 내지 않으며, 세부 분류 정확도와 설명 품질만 낮아집니다.
